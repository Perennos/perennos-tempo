# Product decisions — 23 October 2026

This review used current primary sources and the candidate code at 43ee6d9. Sources explain capabilities; the choices below are engineering judgments for Tempo, not upstream claims that Tempo achieves the same results. No new model, external service, package or paid call was introduced.

| Evidence from primary sources | Decision for Tempo | Measurement or remaining gate |
| --- | --- | --- |
| [Ollama context length](https://docs.ollama.com/context-length) documents VRAM-sensitive defaults and additional memory for larger contexts. | Bound volatile history and keep complete recent turn pairs. Avoid unbounded chat replay. | 12 completed pairs / 12,000 UTF-8 bytes including the new prompt, tested with Unicode and long answers. Bytes are not exact tokens; engine-aware admission remains future work. |
| [Ollama API](https://github.com/ollama/ollama/blob/main/docs/api.md) exposes keep-alive and explicit unload behavior. | Preserve candidate GPU handoff fixes and refusal on uncertain admission; do not silently keep more models resident for speculative speed. | Re-run exact-source Windows/GPU qualification. No latency or throughput gain is claimed by this patch. |
| [Python Tk threading model](https://docs.python.org/3/library/tkinter.html#threading-model) describes event-loop/thread constraints. | Snapshot context before starting work; workers return events; the UI thread commits successful turns and updates widgets. | State tests exercise success, cancellation, oversized drafts, clear-while-busy and stale status events. Native rendering remains Untested here. |
| [RouteLLM](https://github.com/lm-sys/RouteLLM) publishes trained routers, model-pair-specific calibration and an evaluation framework, with models/data linked on Hugging Face. | Evaluate its methodology as a benchmark candidate before replacing Tempo's privacy and admission routing. Do not copy performance claims from a different engine pair. | Build a public synthetic corpus; pin engine revisions; report task quality, refusal rate, latency and memory. No external weights were downloaded. |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) provides a native inference stack with multiple hardware backends and server tooling. | Keep it on the backend evaluation list, rather than introduce another unqualified runtime during installer repair. | Side-by-side Windows/CPU/GPU tests, protocol compatibility and redistribution review before integration. |
| [LiteLLM reliability](https://docs.litellm.ai/docs/proxy/reliability) supports retries, fallbacks and cooldown policies. | Reliability patterns must be constrained by Tempo's owner/privacy policy. Preserve no automatic replay after an ambiguous send and no private-to-hosted failover. | Real loopback transport fixtures verify identity, privacy metadata, redirects and proxy bypass. |
| The [2026-07-28 MCP specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning) adds stateless per-request metadata and `server/discover`, while retaining compatibility rules for handshake-era clients. | Keep the local stdio surface narrow and support modern discovery plus 2025-era handshakes without adding resources, prompts, tasks, HTTP or remote OAuth. | Wire fixtures cover discovery, version negotiation, tools, and stdio framing; exact-build interoperability with an official current MCP SDK remains an acceptance gate. |
| [GitHub matrix jobs](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/run-job-variations) supports OS-specific source checks. | Add Windows source checks alongside Linux while keeping native installation as a distinct workflow. | CI result on this exact head commit; do not infer a working installer from unittest results. |
| [GitHub artifact retention](https://docs.github.com/en/actions/tutorials/store-and-share-data) supports per-artifact retention. | Keep synthetic acceptance evidence for 14 days so review does not depend on a one-day window. | Repository limits still apply; no native workflow was run solely to generate storage. |
| [GitHub attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations) and [immutable releases](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases) distinguish provenance and release integrity. | Specify signing/provenance/immutability as a release gate. Do not add unreviewed signing credentials or claim an unsigned executable is trusted. | Maintainer-approved release policy, rebuilt artifacts and verification evidence. |

## Priorities intentionally held back

A framework rewrite, persistent prompt cache, automatic conversation summarization, telemetry, broad agent tool execution and automatic provider failover would expand memory, dependencies, data retention or trust boundaries. The measurable first pass instead fixes lost follow-up context and opaque support failures without adding dependencies. The roadmap separates implemented source work from native, accessibility and performance qualification.
